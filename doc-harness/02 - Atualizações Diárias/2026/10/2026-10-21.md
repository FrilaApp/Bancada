# 2026-10-21

## O que foi feito
- **Design System MidFi no iOS**: aplicação do design system na tela de Publicação de Vaga (`FrilaApp/frila-frontend`, PR #435); aplicação do design system nas telas de Minhas Vagas e Candidatos (`FrilaApp/frila-frontend`, PR #436).
- **Mapeamento de cenários de API real**: auditoria e mapeamento dos cenários -FRILA_SCENARIO que utilizam dublês, identificando 12 telas com cobertura completa no cliente da API e documentando discrepâncias entre campos do design e schema (`.workers/missoes/2026-10-21-doutor-estranho-cenarios-para-chamadas-reais.md`).
- **Triagem e saneamento de testes de UI**: levantamento e categorização de causas de falhas na suíte FrilaUITests após a chegada do layout MidFi, separando asserções obsoletas de layout, acessibilidade (AX5) e fixtures de dados (`.workers/missoes/2026-10-21-doutor-estranho-falhas-ui-causa.md`); início das correções de testes e acessibilidade (`FrilaApp/frila-frontend`, PR #437).
- **Resiliência e concorrência no backend**: isolamento do pg_cron e inclusão de verificação de convergência estrita no teste de concorrência de limite de teto de despacho (`FrilaApp/frila-backend`, PR #314); estruturação e validação de rotina de backup lógico cifrado (`FrilaApp/frila-backend`, PR #312).
- **Atualização da Bancada**: consolidação do vault público com todos os fatos, notas diárias e status de tarefas do período de 19 a 21/10 (`FrilaApp/Bancada`, branch docs/atualiza-21-10).

## Decisões
- **Isolamento de fixtures e cenários**: retenção de 10 cenários essenciais para testes unitários e de UI pontuais, planejando remoção de dublês obsoletos em favor de testes de integração direta.
- **Saneamento de testes em cadeia**: divisão das correções de UI em etapas independentes (testes legados, acessibilidade AX5 e cenários de dublês) para garantir zero falhas na suíte de testes.

## Bloqueios
- **Regressão de testes de UI após MidFi**: alterações visuais e temporizações de animação nos novos componentes SwiftUI introduziram atritos na suíte automatizada de UI (em estabilização ativa pela equipe).

## Aprendizados
- **Identificadores de acessibilidade em novos componentes**: novos componentes de interface no SwiftUI precisam carregar identificadores semânticos de acessibilidade estáveis para que testes de UI não dependam de busca textual sujeita a mudanças de catálogo.

- Realizar validações ponta a ponta das 12 telas contra o ambiente de desenvolvimento compartilhado.
