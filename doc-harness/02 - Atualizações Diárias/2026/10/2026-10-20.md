# 2026-10-20

- **Design System MidFi no iOS**: implementação dos tokens semânticos e componentes base (passos 5 a 7 do Guia do Fabrício, `FrilaApp/frila-frontend`, PR #425); aplicação do design system e search capsule na tela de feed de vagas (`FrilaApp/frila-frontend`, PR #426); aplicação do design system na tela de detalhe da vaga (`FrilaApp/frila-frontend`, PR #427).
- **Web e canais institucionais**: desenvolvimento da landing page oficial de divulgação do Frila em `Web/` (`FrilaApp/frila-frontend`, PR #428); conexão do domínio público frilabr.com e publicação do site institucional (`FrilaApp/frila-frontend`, PR #433); unificação dos canais de suporte e atendimento usando os endereços do domínio frilabr.com (`FrilaApp/frila-frontend`, PR #429).
- **Conformidade LGPD e segurança**: rascunho do plano de resposta a incidentes de segurança da informação e conferência do registro de operações de dados pessoais (`FrilaApp/frila-frontend`, PR #430).
- **Diagnóstico e persistência de dados no iOS**: diagnóstico detalhado de falha de persistência no build 0.4.0 com caminhos codificados contendo espaços no Application Support gerando CocoaError 260; correção definitiva garantindo caminho decodificado no container e inclusão de teste de regressão automatizado (`FrilaApp/frila-frontend`, PR #431).
- **Testes e documentação iOS**: inclusão de teste garantindo limite estrito de uma retentativa em leituras (`FrilaApp/frila-frontend`, PR #423); teste cobrindo primeiro acesso do contratante com fila nula (`FrilaApp/frila-frontend`, PR #424); atualização das etapas de CI com portões de textos, movimento e datas fixas (`FrilaApp/frila-frontend`, PR #422); remoção de links quebrados no README (`FrilaApp/frila-frontend`, PR #421).
- **Monitoramento e resiliência no backend**: emissão de alerta demonstracao_sob_ataque na RPC verificar_saude ao identificar volume atípico em contas de teste (`FrilaApp/frila-backend`, PR #309); gravação explícita e exigência de DEMONSTRACAO_ATIVA_ATE no deploy remoto (`FrilaApp/frila-backend`, PR #310); resiliência na publicação de vagas em contas de demonstração e semeadura para datas posteriores a 06/11 (`FrilaApp/frila-backend`, PR #311); rotina de purga periódica para dados efêmeros de teste em higienizar_tabelas (`FrilaApp/frila-backend`, PR #185); higienização e tipagem de logs no FCM sem expor corpo bruto (`FrilaApp/frila-backend`, PR #313).
- **Operação e backup**: backup do prod feito e agendado, com diário de configuração atualizado com as mudanças de infraestrutura (`FrilaApp/frila-frontend`, PR #432 e PR #434).

## Decisões
- **Domínio público do produto**: frilabr.com estabelecido como domínio oficial para a presença web e comunicações de suporte da plataforma.
- **Retenção de dados efêmeros**: retenção configurada para 30 dias em entradas de demonstração e 60 dias para falhas de execução no banco de dados.
- **Manipulação de containers locais**: exigência de decodificação de caminhos em URLs locais de arquivo no iOS para eliminar erros de IO decorrentes de percent-encoding.

## Bloqueios
- **Pausa noturna operacional**: interrupção coordenada das tarefas noturnas automatizadas para sincronização de escopos e preservação de recursos do ambiente.

## Aprendizados
- **URLs de arquivo vs caminhos no sistema**: a API de sistema de arquivos do Cocoa trata caminhos com percent-encoding como literais caso não sejam explicitamente decodificados, gerando falha de diretório inexistente quando nomes de pasta no simulador contêm espaços.
